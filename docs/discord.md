Physical source vs post-boot virtual alias: running THC NEM-4 ROM’s readable first 1.96 MiB is identical byte-for-byte to the stock MCU payload 5 MiB higher in physical flash. Comparing at the same numerical offset yields a false encoded-vs-plaintext pair. The GSM virtual image has different origin/extent, so it needs separate tracing.
ROM/IO virtual origins grounded in original code: 0x50000000 comes from the boot header at 0x8C and 0x58000000 is produced by an ARM helper; they are not guesses from a ROM parser or THC address alone.
Startup descriptor lists actually embedded: NEM-4 contains three selectable source tables (0x638, 0x744, 0x830) with counted 16-byte records. Type-1/2/3 flags preprocessing is separate from the actual section/small-page writer. Hardware selection still unknown.
Reset trampoline recovered: entry at 0x320 transitions through 0x3FC stack-switch and literal 0x0F78 second stage. A direct-call-only graph misses most early startup. The corrected graph shows stage 2’s hardware preparation before the MD5 wrapper.
Three ‘external’ entrypoints demystified: 0x0C004748, 0x0C004768, 0x0C0047B4 are loaded by ARM code embedded in the original MCU and copied into scratch, in two phases. Their final predicted state is a mixed NOR mode A/mode B overlay, not an unknown ROM-only black box.
Three NOR chip-type inputs distinguished from fixed global controller selector: bank types are hardware-probed and cannot be read from firmware constants; NEM-4 global selector is fixed 2 and dispatches elsewhere. RH-29 takes a different variable controller path and has different command/type tables.
Two distinct pre-MD5 CBUS submissions: (0x3B,0x10,0x61) early, (0x3B,0x0F,0x29) later, to address-related MMIO accessors. A value 0x0021 is ORed with bit 0x0008 to form 0x0029 in the shadow path. The command selector and actual hardware-side effects remain unknown.
Cross-version firmware lineage: selected early bootstrap/MD5/CBUS instructions are identical across NEM-4 releases (often identical to RH-29 after specific, not universal, code offset +0x60). v3.x and v4.x LCD path differ in three bytes across a 3,200-byte compared range. v4.03 and v4.17 are nevertheless meaningfully different elsewhere.
LCD initialization: Epson S1D15G00-like display command semantics plus row/column loop counts and exact 12bpp display-size arithmetic strongly identify NEM-4 LCD setup. Do not keep describing the 73,216 bytes of CPU MMIO writes as a recovered firmware-decoding stream.
ROM configuration and MMU construction
Original boot code points to low physical 0x80; CPU ROM VA seed from [0x8C]=0x50000000 and ROM config size from [0x90]. I/O VA seed is separately produced as 0x58000000.
Startup lists: NEM-4 0x638, 0x744, 0x830; selector at 0x95C is hardware dependent. They include physical spans and flags, not finished L1 descriptors.
Preprocessing of records and flag changes is distinct from L1/L2 page-table writes. The ROM walker updates a mutable virtual cursor. First-level writer uses L1[VA >> 20]; small-page writer can change an L1 entry associated with an L2 mapping. M25 warns that secondary mapping beginning after the digest end can still share the same 1MiB L1 section as its last byte.
On one verified reset-dataflow path: low section L1[0] receives 0x2E, later 0x43E for temporary descriptor access, and is restored. The post-boot +5MiB remap occurs after the MD5 calls, so the running THC map must not be reused as digest-time input.
NOR-bank results versus global controller selection
Three NOR chip-type results are produced by the hardware identification loop and stored near physical scratch 0x0A01200C. NEM-4’s unrecognized sentinel is 16, RH-29’s 20. Actual NEM-4 bank types are unknown.
A different NEM-4 helper at 0x6200 is literally MOV R0,#2; MOV PC,LR, feeding the separate eight-entry dispatcher. This constant does not mean every flash bank is NOR type 2.
Dispatcher at 0x6208 accesses entry 0x621C→0x623C→0x6258. NEM-4 code shows 19 direct BL sites in this route. M35 identifies this as an LCD path: 0x62B0→0x6448; nested loops 208 × 88 = 18,304 CPU 32-bit MMIO writes, 54,912-byte display-length parameter = 176×208×12/8. Its Epson S1D15G00-like commands indicate controller family, not exact device part.
