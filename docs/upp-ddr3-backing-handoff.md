# Deferred experiment — back two UPP RAM windows with DDR3

Run separately from the CPU pipeline work. Start in the existing integration checkout. Read `AGENTS.md`, `docs/status.md`, the [UPP ownership audit](peripheral-ownership.md#firmware-use-and-the-two-64-kib-allocations) and the [DDR allocation evidence](ddr-diagnostics.md#memory-and-reader).

1. Build an offline BRAM-control vs DDR3-candidate comparison. Reserve two disjoint private 64 KiB spans after checking the firmware, C:, PMM, debug and framework address maps. Route actual guest reads and masked writes for `0c03xxxx` and the generic `0c10xxxx` tail through the existing arbitrated scalar DDR path. Keep the MDI rings/pointers local, their decode priority intact, and `0c06ffxx` on its existing auxiliary path. Keep flash command handling and save dirty tracking confined to their present owners.
2. Check both ends of both windows, equal offsets with different values, partial writes, upload instruction fetch, MDI boundary, cold zeroing and warm retention. Force DDR stalls and reset during a transaction. Check completion once for the right owner, ordering and absence of corruption in adjacent backing ranges. Reuse the board CPU and reset fixtures.
3. Compare the same firmware, DDR latency and completed work from cold boot through upload and Menu. Record per-window accepted reads/writes/fetches, upload time, boot cycles and DDR contention. Use fresh offline output directories and preserve existing simulations and checkpoints. Report functional differences and the first divergent access. The current banks account for 128 M10Ks gross. A later matched fit measures net M10Ks, ALMs and timing. Leave production RTL, PLL and running phone untouched during the experiment.
