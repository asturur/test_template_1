# ZAP register-file area audit (2026-11-11)

## Observed production implementation

The supplied failed-fit hierarchy attributes1,951.9 ALMs and1,280 registers to
`zap_register_file`. This is about4.66% of the device's41,910 ALMs. It stores
40x32 bits once, with four normal asynchronous read muxes and one dedicated
CP15 asynchronous read mux. It is not five copies of register storage.

The generic interface has two binary writes under `i_wen`, plus a background
one-hot write. Priority is reset, then background C over B over A. The selected
D-cache currently drives `o_reg_idx` and `o_reg_dat` zero. Thus the production
background write is inactive and should already be eliminated; deleting its
interface alone is not an area saving. Keep the generic contract for fixtures.

All40 physical slots cannot simply be reduced to16 architectural registers.
They include banked FIQ/IRQ/SVC/UND/ABT registers, SPSRs and internal operands.
Physical33/34 are called dummy registers but are actively used by the micro-op
sequencer, including expanded instructions and exception-return sequences.
RAZ/PC/CPSR are special at issue; hardwiring their RF slots requires a whole-
consumer proof, not just the register names. The generic RF allows raw writes.

CP15's read index is generated by translation of an architectural R0..R15
index in the current CPU mode. That selects a subset of31 physical slots across
all banks, excluding SPSRs and internal dummy registers. A specialized CP15
read selector may exploit this subset, but synthesis may already simplify some
selection logic. Preserve generic test behavior for arbitrary physical indexes.

## Experiments in priority order — not implemented

1. **Word-local write decode, same FF storage and asynchronous read interface.**
   Decode A/B once and retain exact per-word B-over-A/reset priority. Compare
   against current indexed writes; the compiler may already produce equivalent
   hardware. No extra capture/read/write clock is permitted.
2. **CP15 read selector specialization.** First assess its restricted address
   set without sharing a normal read port. Then consider sharing only if the
   existing CP15 state/operand ownership proves normal-read exclusion. The
   dedicated port was added to remove late CP15 selection from normal port A;
   do not undo that timing improvement without a routed comparison.
3. **Replicated RAM/latest-writer storage (Z2).** This is a larger candidate,
   not a direct replacement: synchronous M10K reads and multiple writes must
   fit the existing owned operand capture and commit-refresh contract. Count
   all replicated memories, latest-writer state, write bypass and reset flags.
   MLAB implementation also consumes the logic resource currently scarce.

The current RF already uses compact indexed reads. A prior balanced masked
read-tree implementation was replaced after the operand boundary changed;
repeating that experiment blindly would repeat historical work. Start from
`docs/cpu-operand-stage-contract.md` and the dated RF entries in
`docs/timing-closure.md`. No caches, TLBs, predictor or instruction support is
removed by this audit. Preserve104 MHz as the timing target and no extra CPU
cycles as the acceptance condition for the first two experiments.

## Required validation for a candidate

- Independent40-word scoreboard: all five reads, all destinations, reset,
  A/B/C collisions, multiple C bits, pre-edge reads and post-edge visibility.
- Existing `tests/cpu/cp15_rf/sim.sh`: independent normal/CP15 ownership,
  registered CP15 response and collision behavior.
- Operand ownership/journal tests: stalled packets, simultaneous pop/push,
  current/previous commit refresh, clears and bank/mode changes.
- ARM fixtures for load writeback/base update, LDM/STM, long multiply, SWP,
  CP15 reads/writes, IRQ/FIQ/abort entry/return, SPSRs and user-bank operations.
- Cycle comparison at zero/variable waits, then isolated Quartus area/RAM and
  routed104 MHz setup/hold results. Source simplification alone is not a win.

No implementation, new simulation, synthesis or build monitoring was performed
for this audit. Existing simulations and uncommitted diagnostic work are intact.

## Audio headroom and retained output path

`MISTER_DISABLE_ALSA` removes the Linux PCM mixer; it does not disable core
AUDIO_L/R, HDMI/I2S, DAC or the normal MiSTer core-audio route. Template currently
drives zero samples. Adding phone-generated PCM does not require ALSA.
The current D550 boundary is an MDI stub, not a PCM-producing DSP/codec model.

P7 is now explicitly ARM game PCM audio: no DSP execution or phone-service
sound emulation for this phase. Adapt the donor two-buffer PCM engine and only
the guest playback/API bridge required by games. Its HLE register window at
0x0c1f0000 is an invented emulator interface, not a physical Nokia DSP. Port
maintained new HDL as Verilog-2001. Full NOS/BT compatibility packages are not
a prerequisite; any game-facing software shim must be scoped explicitly.

Measure the producer, output processing that stops optimizing away once audio
is nonzero, DMA/arbitration and guest bridge together. A barely fitting silent
build does not establish enough headroom for audio. Tests cover repeated
start/stop, mono/stereo, rates, last-buffer/underflow, completion/IRQ ownership,
reset, and concurrent LCD/MMC/saves with captured PCM comparisons.
