# ARM920T manual audit: N-Gage core

> Historical audit: the table below predates the associative cache and write-buffer implementation. For current implementation, test results and remaining limitations, see `status.md`; do not treat these original gap descriptions as current.

Latest 2026-11-03: an opt-in associative I/D cache now passes directed CPU tests, including selected MVA/index maintenance and D lockdown. The default build remains the old direct-mapped cache. See the newest status checkpoint for exact coverage and limitations; several table entries below describe the prior baseline.

Reviewed the chapter inventory and software-visible requirements in local ARM DDI 0151C, with the current RTL and existing test notes. This is a gap inventory, not a proof of ARM920T conformance or proof of the exact CPU inside UPP_WD2. Items marked unverified need targeted experiments; see `status.md` for current boot and simulations.

| Manual area | Current assessment and next action |
| --- | --- |
| Ch. 1–2: architecture, programmer model, CP15 | ARMv4T and CP15 exist. The cache-type register advertises 64-way caches, while ZAP caches are direct-mapped (`zap_cp15_cb.sv`, `zap_cache_tag_ram.sv`). Software using way/index operations may therefore behave incorrectly. Determine real firmware use before changing identification. CP15 control bits 11:10 now read zero and bit 14 resets to zero independently of fixed ARMv4T branch behavior; focused unit tests pass. Privileged CP15 handling also needs an exception-semantics audit. |
| Ch. 3: MMU, sections/pages, domains, faults, FCSE | Sections, coarse/fine pages, domains, FCSE, and alignment faults have implementations and selected tests. Large/tiny pages, every permission/domain combination, TLB lockdown, cacheable aliases, external aborts and abort priority are not fully verified. Run targeted tests against the manual. |
| Ch. 4: I/D caches, write buffer and coherence | Newly implemented C=1/B=0 write-through stores are tested for section and small-page mappings, hit/miss, and halfword writes at two latencies. Stores are serialized until bus acknowledgment, not implemented as ARM920's asynchronous write buffer; timing, write-buffer abort behavior and performance differ. C=0/B=1 also lacks an independently modeled write buffer. Full coherence and maintenance during active transactions remain unverified. Existing CPU cache remains direct mapped. An isolated 8-segment/64-way tag/victim prototype with dirty halves and lockdown now has directed tests, but it is not connected to the CPU or synthesized; the end-to-end associativity unit test remains XFAIL. |
| Ch. 2 and 4: CP15 cache/TLB operations | `zap_cp15_cb.sv` does not decode the manual's single-line/index operations individually: unrecognized cache operations fall through to whole-cache clean/invalidate. The drain-write-buffer encoding is now explicitly handled for the current synchronous store path and tested to leave dirty cache lines intact; asynchronous write-buffer and overlapping-transaction semantics remain unverified. Wait-for-interrupt still falls through this default and is not implemented as specified. TLB invalidation is coarse. Test guest-visible effects and fix operations the firmware needs; do not assume all broad invalidations are harmless. |
| Ch. 5–6: clocks and AMBA | Model uses idealized clocks and a Wishbone-facing simulation backend, not the ARM920 clock modes or AMBA timing. FPGA synthesis, MiSTer timing, arbitration and physical UPP bus behavior remain unverified. Timing/throughput differences are not evidence of a functional failure by themselves. |
| Ch. 7: coprocessor interface | CP15 subset exists; other coprocessors, busy-wait and privileged exception behavior need a dedicated audit. |
| Ch. 8–11 and Appendix B: trace, JTAG, EmbeddedICE, manufacturing/test and implementation-defined tests | No equivalent complete physical debug/trace/test hardware is claimed. Prioritize only if firmware uses these interfaces or physical debugging requires them. |
| Ch. 12–13: instruction-cycle summaries and timing | Current core is not cycle-equivalent; 104 MHz timing and phone-speed boot are unproven. Functional tests at multiple memory latencies do not establish timing conformance. |

Priority after the current firmware replay: verify write-through commands and C: behavior in the real run; audit and test CP15 cache-maintenance operations used by that run; examine abort/interrupt interaction and TLB/page attributes; investigate cache geometry/lockdown only with concrete firmware use or phone identification evidence. Do not treat untested entries as implemented or the manual alone as a chip identification.
