# N-Gage CPU pipeline architecture review

**Decision, 16 November 2026.** Build a single-issue, in-order ARMv4T core with a pipelined hit path and an eight-entry in-order completion queue. Give the load/store unit (LSU) its own address adder and ports into that queue. Keep both ARM920-shaped caches at **16 KiB, eight segments × 64 ways × 32 bytes**, their lockdown/replacement and maintenance semantics, and the two 64-entry TLBs. Change the circuitry behind them. The first implementation slice should prove that consecutive resident stores can qualify every clock and commit in order, even to successive words of one line. This targets a measured four-clock recurrence, plus the path currently failing timing. The next slice should let an independent ALU instruction finish privately while an older load is outstanding.

**A new 4× across these workloads at the same clock is beyond the evidence.** Even ideal single issue has a generous six-kernel geometric ceiling of **3.91× at 0:0**, before paying for the wrapper, misses, branches or dependencies. At 2:9, retaining the measured scalar traffic and responder lowers that ceiling to about **3.29×**. Transpose has room for 4× individually. The original JPEG bitmap block executes 22,500 instructions in 89,610 clocks. An independent trace found 2,372 immediate load consumers. With the four-clock load-to-consumer spacing proposed below, its optimistic steady-state issue bound falls to **about 3.03×**. An honest first decision point is substantial measured gains on warm stores, transpose and JPEG, followed by a new ranking. No candidate IPC, area or clock closure has yet been measured.

**Counting convention.** An architectural start belongs to one accepted instruction. A conditional instruction that fails still occupies its instruction slot. A PUSH, a long multiply and the current expanded BL may each issue multiple internal operations. Issue in the trace is a live operand-queue pop into I, before any later squash. Retirement in these ordinary benchmark windows uses the last-uop WB marker; CP15, retry and exception entry need separate architectural events. Report accepted starts, squashes, uops, memory beats and committed instructions separately. An initiation interval (II) of one means adjacent starts are possible. It says nothing about when the first result becomes usable.

## Where the current design spends clocks

```text
WB PC / 512-entry BTB ──► I-TLB / I$ lookahead or one real demand
                            │ exact fetch + permission / shelve
                            ▼
 F → FIFO(16 + registered output) → ARM/Thumb T → predecode P / sequence / RAS(4)
   → decode D / bank map → operand R(2) → issue I → shift/multiply S → ALU A
                                                        │         │
                                  local ALU bypass ◄────┘         ▼
                                         P1 (P0 aliases A) → P2 → M → W / RF
                                          │ checked MVA       ▲    format  commit
                                          ▼                   │
                                     D-TLB / probe B       one owned completion
                                          │                   ▲
                      P2 demand or eligible advancing P1 ─► D$ adapter / access
                                     ├─ direct checked read or tag → way → RAM
                                     ├─ resident data+dirty commit / posted buffer
                                     └─ walk, refill, uncached or ordered bus
```

* **Fetch.** Sequential checked I$ lookahead can deliver one per clock. It starts at the live instruction address +16 bytes and has owner/read/compare/result stages and two stream slots. Only a matching requested address with actual access permission can ACK. A nonmatching fetch becomes an owned demand. A pending fetch without ACK, a full FIFO or an older store with I$ disabled stops PC progress. A redirect can shelve a stale response. The FIFO can absorb fetches while its output is held. Thumb conversion, sequencing, the RAS and coprocessor decode can each hold or redirect the front. [Configured parameters](../rtl/arm/zap_top.sv) · [I$ lookahead](../rtl/arm/zap_cache.sv) · [FIFO read/kill gating](../rtl/arm/zap_fifo.sv) · [Core flow](../rtl/arm/zap_core.sv).
* **Issue and writeback.** D maps banked indices. R has two owned slots and refreshes stale operand bases from writes. I checks load RAW, shift/flags and background locks, then selects the youngest permitted producer. The RF implementation replicates A/B MLAB banks for four ordinary reads and a CP15 read, with separate C data and latest-writer selection. The shifter's late pickup permits adjacent dependent plain ADDs. Complex shifts and the busy multiplier can stop issue. A resolves conditions, carries flags and exceptions, and generates the effective address. With D valid immediately after edge 0, an unstalled ordinary path is R1, I2, S3, A4, P1 at 5, P2 at 6, M7, RF write at 8. Plain issue to RF write is six clocks. M registers the formatted value. Earlier P2 forwarding covers a fault-free aligned ordinary word. [Issue and locks](../rtl/arm/zap_issue_main.sv) · [Operand ownership](cpu-operand-stage-contract.md) · [RF](../rtl/arm/zap_register_file.sv) · [Load forwarding](cpu-load-forwarding.md).
* **The serial boundary.** In `zap_core`, `data_stall = postalu_request_stb && postalu_request_cyc && !completion_valid`. A P2 wait holds upstream execution. M bubbles to avoid repeated retirement and older W effects can still occur. The return register owns data, retry/abort, FSR and FAR. Its registered valid can let a safe P1 use the consuming edge of P2. Immediate matching probes can therefore ACK on successive edges. On a waited access the adapter remembers one launched owner and `cache_access.req_ready` requires IDLE. P1 cannot start a second unresolved tag search while P2 compares tags. The configured D-cache ties its legacy background-refill path off. A store in STORE_COMMIT can overlap a different RAM-B probe, but the next demand still waits. WB clear wins cancellation, an older data fault/retry suppresses younger work, and redirects, SWP, maintenance, CP15 drain and WFI impose their own holds. A held clear level may span several clocks. [Completion credit](../rtl/arm/zap_data_completion.sv) · [D-cache adapter](../rtl/arm920/cache_adapter.sv) · [Demand state machine](../rtl/arm920/cache_access.sv) · [Consume/admit rules](cache-completion-overlap.md).
* **Memory.** The two checked 1 KiB mappings cache separate read/write permission decisions under shared context. Eight checked-line records carry present/absent and way, with no extra line capacity. A new tag search goes through synchronous tag read, compare/way choice and synchronous data. A/B same-slot hazards interlock. The posted buffer already reserves one word/group per clock when space permits, with four groups of up to four words; external issue drains committed beats. Translation miss/walk, dirty replacement, refill, buffer-full/alias/drain, uncached access, SWP and cache maintenance add variable waits. I and D share external service. Current fill installs a complete line, then relooks up the demand. [Cache RAM ports](../rtl/arm920/cache_lines.sv) · [Tag storage](../rtl/arm920/cache_tags.sv) · [TLB](../rtl/arm920/tlb.sv) · [Write buffer](write-buffer-stage-contract.md) · [Streamed transport](cache-line-refill.md).

**Dependency counterfactual.** In the original JPEG flow, count adjacent pairs in which an unconditional scalar load's destination is actually needed by the next unconditional integer ALU or memory address. Exclude store-data-only uses, PC loads, block transfers, predicated consumers and cross-call-boundary artifacts. With in-order operand-ready dispatch and a minimum load-to-consumer gap of G, each pair occupies its own inter-start interval. Ideal issue clocks ≥ 22,500 + 2,372 × (G−1). G=3/4/5 gives same-clock ceilings **3.29/3.03/2.80×** before wrapper, redirects, multi-beat operations and timing. This is an invocation issue-span model with ideal boundaries; issue and WB marker edges may differ by pipeline fill/drain. Zero counted pairs in transpose does not imply zero dependency stalls. It loads directly into store data, a class deliberately excluded and a reason to provide a late store-data path. [Trace counts and inclusion rules](evidence/cpu-pipeline-review-20261116.json).

**What would have to change for 4×.** At 78 MHz the JPEG objective is 22,402.5 clocks per block. Relative to the 29,616-clock optimistic G=4 issue model, roughly **7,214 more clocks** must disappear even with perfect prediction and no other stalls. A path to that target would need much earlier or late-consumed load operands, broader multi-instruction execution *and retirement*, or a combination with measured coverage. The restricted pair screen below finds just 657 opportunities. Triangle would require at least 1.32 original instructions/clock and matrix at least 1.08, ignoring their wrappers. Delayed full fill would need about **2.75 clocks per external word** including all CPU work to meet 50,327 clocks. A major change in backing write service is indispensable for that case. Define any full-app 4× target with the same original workload, clock and I/O configuration before drawing a phone-wide conclusion.

**Clock sensitivity.** At 78 MHz today's JPEG median is 1.149 ms per block (~870 blocks/s). As a design scenario, halving its cycles to 44,805 would give 0.574 ms (~1,741 blocks/s) at 78 MHz and 0.431 ms (~2,321 blocks/s) at 104 MHz. Architecture gain in both cases is 2×. At CPI 1 the peak is 78 or 104 million architectural instructions/s; at CPI 1.5 it is 52 or 69.3 million/s. Wall-clock projections assume unchanged cycles and service measured in core clocks. Fixed-time memory/peripherals and contention violate that assumption. Actual PLL stays at 78 MHz.

## Recommended cycle contract

Use one CPU clock for prediction, execution, caches, TLB and commit. Retain existing external arbitration, CDC and SDRAM clock/phase interfaces. Each stage owns a valid record and consumes it once. A blocked stage holds its payload stable. At a potentially long boundary, use registered free credits and a one-record skid for the token already in flight. Include that token in capacity. There is no combinational ready chain from a memory ACK, through all commit slots, into the AGU or fetch PC.

**Frontend and operands.** F0 launches a canonical PC, ARM/Thumb state and fetch generation to the BTB and line stream. F1 accepts response/tag ownership, F2 selects the ARM word or Thumb halfword and enqueues its PC, state, predicted next PC, length and fetch-fault context. Stage D decodes, determines the physical bank and allocates the next in-order record; stage R obtains synchronous RF bases/producer tags; X starts a ready instruction. A sequential stream resident in the two line buffers can fill F0/F1/F2 on consecutive clocks. The full I$ lookup can run ahead on predicted sequential lines. Wrong or absent predictions pay the synchronous lookup and restart latency. Suffix/prefix handling preserves the architectural LR and allowed interrupt boundary of Thumb BL, including a page fault or interrupt between its two halfwords. Keep the existing safe path for complex encodings until the independent architectural trace proves equivalence.

**Execution and cache.** In this table X0 means inputs stable during cycle 0. A result registered at its end can be used during cycle 1. Credit and permission hits are assumed unless shown. The stage numbers are design targets, not a simulator measurement.

Credit sizing matters as much as the stage diagram. For F0 at 0 with all hits, F1/2 at 1/2, D3, R4 and X5, the first plain ALU can commit at 6–7, a checked load at 9–10. Allocating at D gives the hot load roughly 6–7 cycles to retire, plus a registered credit return. Eight slots can cover that pipeline at II 1 only if returned credits reach D in time. For a full-tag hit committing at X+7, D-to-reusable-slot can reach ten clocks, limiting eight slots to about 0.8 starts/clock even with D-port II 1. Count the actual allocation-to-reuse edges; do not stretch the all-hit claim to every hit class. Size the slow path for correctness first.

A one-cycle ALU recurrence requires a local X-result/flags path. Keep the source tag selection registered from R, and supply short, fixed bypass lanes for adjacent ALU and late LSU results. For a held R record, refresh the tag/value when its producer completes or retires. Compare using physical bank + producer ID, including current commit-to-read collisions. Allocate both base and load destinations as one instruction. Keep a small youngest-producer map indexed by physical destination, plus a flags entry. At D read the old bindings before recording this instruction’s destinations, and save each overwritten binding in the slot. This supports consecutive writers of the same register, including ADD chains and post-indexed base updates, without searching eight full data words at issue. At retirement clear a binding only if it still points at that exact owner. On squash unwind killed entries newest-first, restoring a prior binding only if its owner is still live, otherwise select the committed RF. Walk one killed slot per cycle, up to eight; target fetch overlaps repair and target D waits for completion. The X6 branch example assumes repair finishes by D4. Longer rollbacks add the uncovered clocks. Within one owner the load result overrides its own base on an alias, matching the effective B-over-A priority. Unavailable youngest writers mask older data. Captured operands or stable producer tags protect WAR. Store sources bind before installing their own writeback destination. Decode tracks a separate NZCV producer, including carry and shifter carry. A failed predicate forwards the predecessor binding/value to every waiting subscriber and makes no RF/flag write. Preserve that predecessor until the conditional owner resolves, or hold its issue until the incoming value is available; a younger reader must never receive a fabricated write. Serialize mode/T/SPSR changes and multi-destination exceptions. Normal single-result operations use one RF write; provide the second write for paired architectural effects.

A long miss gives a bounded benefit. Suppose L0 is head and still waiting at cycle 12. Up to seven younger macro records may be occupied by independent work. At eight allocated entries, stop D and eventually F. No younger architectural RF write, flags, device read or store has occurred. Once L0 succeeds, retire it and up to one successor per following clock. A second miss initially parks its owner in age order and cannot acquire the external bus. If the next unissued instruction actually needs L0, in-order X stops there even with credits available. Increasing queue depth cannot fix that RAW chain.

### Cache ports, prediction and slow paths

* **Keep the fast path narrow and fully owned.** The full-tag path can launch a segment tag read for request i+1 while i compares in local groups of eight and i−1 uses the data port. Permission reuse and way hints are checked independently. The eight checked-line entries are hints to the real 64 ways, including the store-absence case. Only once checks pass can a value become usable. Full-tag and short hits may reach B on the same clock; oldest ready wins, the loser keeps its stage credit and retries the *port* without repeating the instruction. An annotated request/response stream should prove no more than one B read, one A mutation and one LSU completion per clock. Bounded older priority prevents starvation. Use a word-sized output at the LSU; select the 32-bit bank locally. Retain 256-bit paths only for line install/eviction where the interface needs them.
* **Make store dirty updates sustainable.** Existing eight 512×32 line banks give per-byte A writes and synchronous B reads. For sustained stores, split the two sticky dirty half-line bits into independently settable storage, or demonstrate equivalent atomic merging on successive writes. Two narrow synchronous RAMs indexed by {way,segment} can each write a constant one on commit; clean/fill writes zero with exclusive mutation ownership. An indexed victim read occurs only after earlier commits drain. Preserve valid state separately so reset need not clear every RAM bit. On a mixed-port same slot, stall/replay B or bypass exactly the proven byte lanes. Randomize undefined RAM collision data in tests. Fill, victim, maintenance and lock changes revoke leases and all stale way/permission/probe records. If eviction, invalidation or version wrap threatens a live intent, drain it or force revalidation. Fully associative bank semantics include MVA match, saved victim PA and both dirty halves. [Line banks](../rtl/arm920/cache_lines.sv) · [Current per-way dirty packing](../rtl/arm920/cache_tags.sv).
* **Use a small recoverable predictor.** Keep the 512-entry tagged BTB and two-bit direction state as the baseline. Include source halfword position and instruction state in the lookup key, and store target state separately from the canonical target PC. F predicts direct branches/calls/returns if a checked target is available. D corrects a known direct target or misclassification; X verifies condition, target, link and state, including BX; load-PC waits for its value. Use the existing depth-four RAS first. Keep a committed copy plus four unresolved prediction checkpoints holding the entire four-entry pre-update stack, pointer, depth, action and owner. Pointer-only recovery loses entries overwritten by speculative pushes on a full stack. Snapshot on accepted action only. Restore the correcting branch's snapshot, apply its actual action once, kill younger snapshots, retain older ones. For interrupts/retry reset speculation to the committed stack at the actual boundary. Degrade an underflow/overflow prediction to BTB/sequential as appropriate, cap checkpoint allocation and stall or stop speculative RAS mutation when full. Retire-confirmed BTB training once per branch; repeated alias, condition failure and killed return cannot train. On read/write collision use an explicit selected old/new policy or skip the prediction. Do not require a register rollback on the PC→PC path. [Existing BTB](../rtl/arm/zap_btb.sv) · [Existing POP/BX recognition](jpeg-next-performance.md).
* **Miss policy, three distinct experiments.** Start external D-side walks, victim selection, writebacks and fills at the architectural head, once all older fault and redirect decisions are settled. Younger probes can read existing tags and data privately; they cannot allocate a D line, advance replacement/lock state, start a walk or dirty a victim. Speculative I lookahead first probes resident permitted code; require an owned, safe fetch miss before any external line request. Frontend/ALU may compute privately behind it. A walk, inherited retry, dirty eviction or refill has one owner; freeze victim, reservation and all beat progress. Abandoned speculative I fills must release transport even on error. (1) Critical-word-first changes the order of the 32-byte transport. The current aligned-base stream has implicit beat order. Negotiate a start offset and wrap/beat index with each backend, or compare an explicit scalar leading read plus line request and charge the duplicate traffic. (2) Early restart forwards a complete requested word from a fill buffer to its owner before line install. Keep a beat-valid bitmap, retain the external owner, and hold retirement/younger effects until final success wherever a later beat can invalidate or retry the demand. Early *retirement* requires proof that a later fault cannot apply to the returned access. (3) Hit-under-fill permits younger independent, permitted normal-memory hits to other slots; block victim/same-line, aliasing posted stores, dirty eviction, walks and maintenance. Add one miss record with PA/MVA, way, validity, error, consumer and kill state; complete younger hits only into reserved slots. Stage these independently. Cold transpose shows a genuine miss tail; warm JPEG and slow posted fill give little reason to fund it first. [Current install and error handling](../rtl/arm920/cache_refill.sv) · [Speculative fetch deadlock](speculative-fetch-deadlock.md) · [Historical controller measurements](memory-performance-baseline.md).
